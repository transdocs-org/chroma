# 配额与限制

为确保多租户环境的稳定性与公平性，Chroma Cloud 对所有面向用户的操作施加了输入和查询配额。这些限制旨在大多数工作负载的性能、可靠性和易用性之间取得平衡。

{% Banner type="tip" %}
大多数配额可根据请求增加。如果您的应用需要更高的限制，请[联系我们](mailto:support@trychroma.com)。
{% /Banner %}




| **配额** | **值** |
| --- | --- |
| 最大嵌入维度 | 3072 |
| 最大文档字节数 | 16,384 |
| 最大 URI 字节数 | 256 |
| 最大 ID 尺寸字节数  | 128 |
| 最大数据名称尺寸字节数 | 128 |
| 最大集合名称尺寸字节数 | 128 |
| 最大元数据值尺寸字节数 | 256 |
| 最大元数据键尺寸字节数 | 36 |
| 最大元数据键数量 | 16 |
| 最大 where 条件数量  | 8 |
| 全文搜索或正则搜索最大长度 | 256 |
| 最大返回结果数 | 100 |
| 每个集合最大并发读取数 | 5 |
| 每个集合最大并发写入数 | 5 |
| 最大集合数量 | 1,000,000 |
| 每个集合最大记录数 | 5,000,000 |
| 从根节点出发的最大 fork 边数 | 4,096 |

这些限制根据请求或集合分别应用。例如，并发读/写限制是按集合独立统计的，全文搜索限制针对输入字符串的长度，而不是搜索的文档数量。

关于 fork 边数限制以及 fork 时的配额错误处理的详细信息，请参阅[集合 Fork](./collection-forking)。

如果您预计会接近这些限制，请提前与我们联系，以便我们确保您的账户已进行相应的配置。
